# Arab ShipBroker — Data Sync module: redesign brief for Claude Design

Prepared 9 Sep 2026 from the code (`components/admin/data-sync/*`, `lib/sync/*`), the live database and the owner's review screenshots of 8–9 Sep. Paste the section **"The prompt"** into Claude Design as-is; the sections before it are the evidence, the section after it is for implementation.

---

## 1 · What exists today (the redesign must keep every capability)

Owner-only module at `/admin/data-sync`. Five tabs, three intake sources, one pipeline: parse → stage a **batch** (`sync_batch` + `sync_staged_row`) → diff each row against the live row and against what the same source said last time → **data-quality gate** → Review → commit with a before-image → undo.

| Tab | Controls and behaviour that must survive |
|---|---|
| **Sync Workspace** | Workbook drop zone (.xlsx, max 10 MB, "Choose file") · **Circulation inbox card**: Sync now, "Fetch mail since" date (default = last successful sync; failed classification never moves it), "Test with a pasted email" dry run, a streamed log (connect → fetch → classify N/M batches with the active model → stage → ✓ / ✗ lines) · **WhatsApp intake card**: Inbox (N) list with delete / clear, Process pending, "Test with a pasted message" · **Recent batches** list: label (UP-date / Email sync · time / WA · sender · time), status (DRAFT · COMMITTED · UNDONE · FAILED), per-sheet counts, Review / Discard / Undo per batch |
| **Review** (one batch) | Summary bar: source icon, label, status, file name, four figures (to insert · to update · invalid · flagged), **Sync all (N)**, Discard or **Undo batch** · Sheet strip with per-sheet counts and lock icon when a parent sheet must be committed first ("Commit Ports first" — cargo references ports; Sync all commits in dependency order) · "Changes only" toggle · Server-paged table (Prev / Next), select all / per row, **Commit selected**, **Commit <sheet>** · Row colours NEW / UPD / unchanged / ERR, changed cells show old → new, flagged cells highlighted, flag list per row (errors · warnings · info) including data-quality flags `DQ-XXX · message` with an info line "blocked by the data-quality gate on channel sync" · Pencil → **Edit staged record** drawer (typed fields per column, re-validates and re-runs the gate on save) · **Source drawer** for e-mail / WhatsApp rows: original message (or WhatsApp contact card), extracted fields, **Find matches** (live + staged drafts, band + origin), **Send summary to contact** (masked teaser, WhatsApp) · **Post open positions** (vessels sheet → `vessel_availability`) · "kept the database value for …" info flags on re-upload |
| **Database Preview** | Ten tables (cargo listings, ports, vessels, flag states, companies, commodities, market names, grain list, IMSBC codes, CSS categories) · server search + paging · inline edit per typed column (enum, int, num, bool, text) · Add record (not for cargo listings) · Delete with confirm · multi-select → **Edit a field on all** / **Delete selected** (cap 500, one undo group) · **Recent edits** drawer: every edit, add, delete and bulk group with **Undo** · errors in plain words (FK, duplicate, required) |
| **Manual Review** | Two queues with pending badges: **Commodities to map** (raw name, sample REF, source; Assign regime dialog → regime + official code, cargo type derived; Ignore) · **Vessels without IMO** (name, built, DWT, type, flag, open port / zone / date, direction, sender; Equasis deep link and **paste box** that fills IMO, GT, NRT, built, flag, registered owner, commercial manager, ISM manager; searchable flag field over all 192 registers; Save changes, **Sync with IMO**, **Sync without IMO (temporary)**, Ignore; the sync writes the register, links the three companies, posts the OPEN position; the data-quality gate on the review channel refuses e.g. an unknown flag) |
| **Settings** | **LLM keys**: add / activate / delete, one active, vendor list (Anthropic, OpenAI, Google, Mistral, other) with model suggestions, key hint only, Vault storage, legacy-key importer, Test · **Circulation inbox**: provider preset / generic IMAP, host, port, user, password (Vault), folder, search query, enabled, Test connection, watermark shown with reset · **WhatsApp**: provider (Meta Cloud API or QR-linked worker), pairing status / QR, acknowledgement template, enabled |

Also present and to be kept: rail badge = Manual Review backlog (63 + 45 = 108 today); the admin banner "changes affect the live platform"; the warn strip "commits are reversible with Undo batch"; SSE progress for the inbox; job_runs rows per inbox sync; the contacts registry binding (every broker cell and sender gets a `contacts` record; erasure in Companies).

Sizes today: 12 batches (upload 4, e-mail 6, WhatsApp 2), 6,065 staged rows, 807 committed, 119 rows with a DQ flag; latest workbook 619 rows across five sheets; queues 63 commodities · 45 vessels.

## 2 · What the owner hit this week (the problems the design must solve)

1. **Lost mail.** The model refused a batch ("payment required"); the run reported "no records" and moved the start point. Fixed in code (the point only moves on a full success; a date picker sits on the card), but the log wall gave no clue where the mail went. The design needs a run summary that says what happened and what to do.
2. **Re-upload noise.** 380 "updates" for a file that had barely changed: normaliser drift (packaging split, vessel-type mapping, LOCODE aliases) and database edits being overwritten by the old file. Fixed in code (cells the workbook did not change keep the database value) — the design needs a three-way conflict view (file · database · last upload) and a plain explanation of *why* a row is an update.
3. **Duplicates across sources.** The same stem from the workbook and a circular, the same ship with and without IMO. Rules DQ-U03 / U04 now find them; the design needs a merge flow inside Review.
4. **Flags without meaning.** "Needs fixing" told the owner nothing. Flags now carry rule codes; the design should show the rule, the cell, and the fix in place.
5. **Manual Review friction.** Flag list too long to scan (fixed with search), Equasis lookups by hand, IMO mandatory (temporary sync exists but hidden), three manager fields missing at a glance.
6. **A synced vessel "not on the dashboard".** It was there; the page was cached. The design should close the loop: after a sync, show where the record now lives and link to it.
7. **Privacy.** Broker and sender names sat as free text; the contacts registry now exists. The design should show the contact chip, not raw text.
8. **Three cards, three vocabularies.** Upload, inbox and WhatsApp each look and behave differently; there is no health view (inbox connection, key budget, worker pairing, failed jobs), no schedule, no history across sources, nothing usable on a phone.

## 3 · Platform facts the design must respect

- ASB design system: navy `#0D2545`, steel `#2C5F8A`, blue `#24486B`, baby blue `#E6F1FB`, tonnage blue `#7BB8F0`, canvas `#F5F7FA`, ink `#1A1A1A`, line `#DDE5F0`; status green `#2E8B57`, amber `#A66A0C`, red `#A83A3A` with tinted backgrounds; Inter with tabular numerals; terminal cards (2 px ridge, 16 px radius, soft navy shadow); 10 px radius buttons and inputs; 11 px/600 uppercase badges; navy rail, navy topbar. **No orange or yellow.** The admin console and the Data quality module already use this system (`app/(admin)/admin.css`, `admin-dq.css`) — the redesign reuses the same table, badge, drawer, filter-bar, toast-with-Undo and confirm-dialog vocabulary so the two modules read as one product.
- Owner-only; a future "dq/it" preset may view. Every write is reversible: batch undo, edit undo, gate re-check.
- The data-quality gate is the single validation service: staging (`sync` / `pipeline` channels), row edit, Manual Review sync (`review`). Rules and channel modes are edited in Data quality → Gate; Data Sync only shows their results.
- The LLM is one Vault-stored vendor-agnostic key (Gemini today); every call is metered; PII is masked before text reaches the model.
- Sizes: tens of thousands of cargoes a year; staging must stay server-paged; the inbox sync runs within a 300 s route with streamed progress.

## 4 · The redesign concept (what to ask for)

Six screens replace the five tabs, same functions, one vocabulary:

1. **Intake** (replaces Sync Workspace). One page, three **channels** as identical rows, not three different cards: Workbook · Circulation inbox · WhatsApp. Each row: status chip (connected · needs attention · disabled), last run and result, next scheduled run, the single primary action (Upload / Sync now / Process pending), a secondary "Test with a sample". Under it a **run panel**: a five-step stepper (connect → fetch N → classify n/N with the model → stage → gate) with live counts, then a **result card**: rows staged (new · updated · unchanged · blocked · warned), rows queued for Manual Review, what the gate blocked and why, and one button "Open in Review". Errors are sentences with a next step ("The model refused the request: payment required. The start point stays at 7 Sep 04:18; add credit in Data Sync → Connections and run again"). A **health strip** at the top: inbox connection, key and budget used today, WhatsApp pairing, failed jobs in the last 7 days.
2. **Review** (a batch). Summary strip first: source, label, five figures (new · updated · unchanged · blocked · warned) as clickable filters, dependency note, **Commit clean rows** as the primary action (commits everything not blocked, in parent-first order), Discard / Undo. The table is grouped by **outcome** (Blocked → Warnings → Updates → New → Unchanged) with the sheet as a column and chip filter, not by sheet first. Each row: key, human label, what changed (old → new per cell), flags as rule chips with the field name. A **row drawer** with four panels: Changes (three columns: file · database now · last upload, per cell "take file / keep database"), Checks (every DQ flag with the rule text and an inline fix box that re-runs the gate), Source (the circular or WhatsApp message with the extracted fields highlighted in the text, the sender as a contacts chip, Find matches, Send summary), History (this key's previous syncs and edits). **Duplicate pairs** (DQ-U03 / U04) appear as a merge card: side by side, pick the surviving key, the other closes. Keyboard triage (j/k, c commit, b block-explain, e edit). Commit and undo confirm with the undo path named.
3. **Database** (replaces Database Preview). Same ten tables, same CRUD, but the same table component as Review and Data quality: sticky header, dense rows, typed cells, filter bar, saved views; **Recent edits** becomes a right drawer available everywhere with grouped undo; a record page (drawer) shows the row, its DQ issues, its sync history, its contacts.
4. **Queues** (replaces Manual Review). One list with two filters (Commodities · Vessels) and bulk actions. Commodity dialog as designed in the Data quality brief (regime → cargo type derived, official code required, hazard class A/B/C + MHB + marine pollutant). Vessel dialog: Equasis panel first (deep link + paste box that fills every field, with a diff against the circular), the three company fields as contacts chips, searchable flag, a **status ladder** (needs IMO → temporary sync → verified) and a follow-up list of vessels synced without IMO. After a sync, a confirmation card shows where the record now lives (register row, open position, dashboard) with links.
5. **History** (new). Every batch, every run, every edit group in one timeline with filters by source and outcome; restore points; "compare with previous upload".
6. **Connections** (replaces Settings). Three cards with the same anatomy: status, credentials in Vault (hint only), Test, schedule. Inbox: schedule (nightly at HH:MM, or manual), start point with reset, folder and query. LLM: keys, active key, daily budget (shared with Data quality). WhatsApp: provider, pairing, acknowledgement template with preview.

Cross-cutting: one badge vocabulary (NEW / UPD / BLOCKED / WARN / OK), toasts with Undo, confirm dialogs naming the undo path, the topbar pill for a running sync (like the Data quality run pill), print/export of a batch summary, a 390 px read-only layout for Intake health, run progress and queue counts, tooltips on every control.

## 5 · The prompt

> **Redesign the Data Sync module of the Arab ShipBroker admin console** at `/admin/data-sync`, keeping every existing capability and moving it onto the ASB design system so it reads as one product with the Data quality module. Arab ShipBroker is a dry-cargo chartering marketplace (Gulf, Red Sea, Mediterranean, Black Sea). Data Sync is the owner's intake room: broker circulars arrive by e-mail and WhatsApp and are read by an AI pipeline, a workbook is uploaded twice a month, and everything is staged, reviewed, checked by the data-quality gate and committed to the live database with a full undo trail.
>
> **Design system (mandatory).** ASB tokens: navy `#0D2545`, steel `#2C5F8A`, blue `#24486B`, baby blue `#E6F1FB`, tonnage blue `#7BB8F0`, canvas `#F5F7FA`, ink `#1A1A1A`, line `#DDE5F0`; status green `#2E8B57`, amber `#A66A0C`, red `#A83A3A` with tinted backgrounds; Inter with tabular numerals; terminal cards (2 px ridge edge, 16 px radius, soft navy shadow); 10 px radius buttons and inputs; 11 px/600 uppercase badges; navy rail and topbar. **No orange or yellow.** Reuse the console's table, badge, filter bar, right drawer, toast-with-Undo and confirm dialog exactly as the Data quality module uses them. Density: 13 px body, 11 px labels. Tooltips explain every control.
>
> **Vocabulary the screens must use correctly.** Sources / channels: workbook upload, circulation inbox (IMAP), WhatsApp intake. Batch (a staged import), staged row, sheet (cargo listings, ports, vessels, companies, commodities), business key (REF · IMO · LOCODE · name), classification (new · updated · unchanged · invalid), flags (error · warn · info) and data-quality flags with rule codes (DQ-C07, DQ-V03 …), gate channels (sync · pipeline · review), commit, undo batch, before-image, watermark ("fetch mail since"), Manual Review queues (commodities to map, vessels without IMO), Equasis, contacts registry, provisional refs (EM-, WA-).
>
> **Capabilities to keep, screen by screen (real).** Intake: workbook drop zone (.xlsx ≤ 10 MB); inbox Sync now with "Fetch mail since" (default = last successful sync, never moved by a failed classification), dry run with a pasted e-mail, streamed progress; WhatsApp inbox list, Process pending, pasted-message test; recent batches with status and per-sheet counts, Review / Discard / Undo. Review: summary figures (to insert · to update · invalid · flagged), Sync all in parent-first order ("Commit Ports first" — cargo references ports), per-sheet and per-selection commit, Changes-only toggle, server paging, row colours by class, old → new per cell, flags per row including `DQ-XXX · message` and the gate's "blocked on channel sync" note, Edit staged record drawer (re-validates and re-runs the gate), Source drawer (original message, extracted fields, Find matches across live and staged, Send summary to contact), Post open positions, "kept the database value for …" info flags on re-upload. Database: ten tables with search, paging, typed inline edit, Add record (not cargo), delete, bulk edit / delete (cap 500, one undo group), Recent edits with undo, plain-language errors. Manual Review: commodity queue with Assign regime (regime → cargo type derived, official code, hazard class A/B/C, MHB, marine pollutant) and Ignore; vessel queue with Equasis deep link and paste box (fills IMO, GT, NRT, built, flag, registered owner, commercial manager, ISM manager), searchable flag over 192 registers, Save, Sync with IMO, Sync without IMO (temporary), Ignore, the gate refusing an unknown flag on the review channel. Settings: LLM keys (one active, Vault, vendor list, test, legacy import), inbox connection (provider preset, host, port, user, password in Vault, folder, query, test, watermark reset), WhatsApp (provider, pairing / QR, acknowledgement template).
>
> **Problems to solve (from the owner's review of 8–9 Sep, real).** A refused model call once lost mail silently — runs must end with a plain result and a next step. A re-upload showed 380 updates that were normaliser drift and overwritten edits — show a three-way conflict (file · database · last upload) per cell with take-file / keep-database. Duplicates arrive across sources — surface DQ-U03 / U04 pairs as a side-by-side merge inside Review. Flags said "Needs fixing" without a cause — show the rule, the cell and an inline fix that re-checks. Manual Review needed a searchable flag list, Equasis in one paste, the three manager fields, and a visible temporary-sync state. After a sync the owner could not see where the record went — close the loop with links to the register row, the position and the dashboard. Sender names were free text — show contacts chips bound to the registry. Three cards behaved differently and there was no health view, no schedule, no history, no phone layout.

> **Screens.**

>
> **Deliverables.** Desktop 1440, laptop 1280, phone 390; component specs for channel row, run stepper, result card, batch summary strip, outcome-grouped row, row drawer (four panels), merge card, queue item and vessel dialog, connection card; empty / running / failed / stale states; a data-binding table listing for every widget its source: existing tables and RPCs (`sync_batch`, `sync_staged_row.flags`, `sync_commit_audit`, `record_edit_audit`, `commodity_review_queue`, `vessel_review_queue`, `job_runs`, `sync_source_state`, `email_ingest_config`, `llm_credential`, `whatsapp_message`, `whatsapp_config`, `contacts`, `fn_dq_gate_batch`, `commit_sync_batch`, `undo_sync_batch`, `resolve_vessel_review`, `resolve_commodity_review`, the `/api/sync/email` stream) and what is new (a schedule table for the inbox, a history view over batches and edit groups, a merge RPC for duplicate pairs).

## 6 · Implementation notes for after the design

- **Schedules.** `sync_schedule` (source, cron, enabled, last_run_id) driven by a Vercel cron like `dq-nightly`; the inbox run already streams and logs to `job_runs`.
- **Run result card.** Extend the SSE `done` event with the gate summary (blocked, warned, queued) — `stageBatch` already returns `gate`.
- **Three-way changes.** The staged row carries `payload` (file), `diff.old` (database at staging time) and the previous committed payload is fetched in `stage.ts`; persist it as `previous` on the row so the drawer needs no extra query.
- **Merge RPC.** `merge_duplicate_rows(table, keep_key, drop_key, actor)`: repoint references, close the dropped row, audit both.
- **History.** A view over `sync_batch`, `sync_commit_audit` and `record_edit_audit` grouped by day; restore = existing undo RPCs.
- **Queues.** Add `follow_up` flag on `vessel_review_queue` for temporary syncs; the confirmation card uses the ids `resolve_vessel_review` already returns.
- **Shared components.** Lift the Data quality module's table, drawer, badge, filter bar, toast and confirm into `components/admin/ui` so both modules import one set.
